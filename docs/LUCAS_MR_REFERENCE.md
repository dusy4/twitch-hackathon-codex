# Room-anchored character reference — Lucas Martinic

Reviewed 2026-10-29 after the owner supplied the tweet, portfolio and screenshots. The target is now explicit: a volumetric character staying on a physical desk/floor while the camera moves, including surface contact and correct occlusion where available. An orbitable virtual scene alone does not satisfy this target.

## Direct evidence

- [Original author post](https://x.com/lucas_martinic/status/2115027510492561477), posted Oct 27, describes native 3D at 90 FPS and PICO CLI. It does not identify all runtime libraries. These performance claims belong to the author, not our benchmark.
- [Author portfolio](https://lucasmartinic.com/) describes scene understanding, depth-enabled character interaction and camera-to-world object anchoring in related prototypes. Its Mario entry still has no implementation walkthrough. The related sound-object prototype explicitly retains depth and camera capture timestamps to align delayed detection results.
- The public author GitHub repository list was inspected through GitHub's API. No matching release of the new Mario demonstration was present in that returned list. This is not proof that no private/unlisted repository exists.
- The tweet's public syndication metadata supplied an actual 1080x1080 MP4. Downloaded locally for reference only: `.data/research/lucas-martinic/mario-mr-reference.mp4`, 40,211,309 bytes, 80.576 seconds. SHA256 `fe8f9391735bc5a20df3c7021efee7574694df5cde15d8c2041f292954f4b9ef`. Frames at 0/22/32/38/55 seconds were extracted and inspected. At 22 seconds the game world is a spatial window; at 32 seconds the camera looks down into the physical floor area; at 38 seconds a hand holds the character over the desk. A monocular recording demonstrates appearance, not stereo calibration or a reproducible tracking benchmark. Reference media stays ignored and is not bundled with RaidRift.

## Corrections to the screenshot's Grok reply

The reply is not evidence. The original post confirms PICO CLI but not Unity version, the specific PICO scene APIs, exact interaction toolkit, libsm64 package selection or unreleased hardware. Those are not recorded as facts. Secondary reporting says Lucas restarted from a full decompilation rather than simply extending the older project; until the author publishes source, the precise current stack remains unconfirmed.

## Implementation direction

Keep the verified, licensed character assets and existing authoritative multiplayer service. Add actual runtime pose + surface hit-test + anchor placement through WebXR where supported; preserve a truthful unsupported-device state. For native phone room tracking, continue AR Foundation. For a Quest/PICO target, use its documented scene/depth/interaction SDK adapter once the device is known. Surface contact/navigation and depth occlusion are separate acceptance gates. Do not label image-coordinate following, a fixed virtual plane, emulator output or this reference video as a passing live AR implementation.
