# ADR 004 — buildable Android AR through SceneView/ARCore

Date: 2026-10-29. Status: implemented Android debug build/JVM/lint slice; physical phone and native runtime gates open. Owner confirmed Android phone.

The owner supplied a room-anchored mixed-reality character reference and authorized any genuinely 3D character model. Native Android is the handoff's first mobile target. The Unity source remains uncompiled because no licensed editor is configured; browser WebXR now exercises genuine tracking/contact APIs, but cannot by itself establish captured camera+virtual broadcast output.

Select **SceneView/ARCore + Kotlin/Compose + Filament** for an additional native Android client. This is a justified native equivalent to AR Foundation: ARCore supplies pose/planes/anchors and supported device depth; Filament renders the same licensed skeletal GLB cast; SceneView supplies the lifecycle and scene adapter. It avoids requiring a Unity account/license merely to produce an APK. The existing Unity/ARKit source is preserved, not declared validated or replaced for iOS.

Primary sources reviewed before native implementation:

- [SceneView v4.62.0 release](https://github.com/sceneview/sceneview/releases/tag/v4.62.0) and [pinned API reference](https://raw.githubusercontent.com/sceneview/sceneview/v4.62.0/llms.txt): model instances, explicit named animation (auto-playing all clips is wrong), feet-aligned model origin, anchors, tracking callbacks, capability downgrade and lifecycle handling.
- [Pinned build catalog](https://raw.githubusercontent.com/sceneview/sceneview/v4.62.0/gradle/libs.versions.toml) and [Gradle wrapper](https://raw.githubusercontent.com/sceneview/sceneview/v4.62.0/gradle/wrapper/gradle-wrapper.properties): SceneView 4.62.0, Kotlin 2.4.21, AGP 9.4.1, Gradle 9.8.1, Filament 1.72.1, ARCore 1.57.0. The library requires Java 21 bytecode and compile SDK 37. Do not override Filament independently of its compiled material ABI.
- [Official AGP 9.4 compatibility](https://developer.android.com/build/releases/agp-9-4-0-release-notes): API 37 support and Gradle 9.6+; the upstream wrapper's 9.8.1 satisfies it.
- [Google ARCore depth guide](https://developers.google.com/ar/develop/java/depth/developer-guide): depth is disabled by default, must be support-checked and enabled, and absent depth frames are normal during poor tracking. Configuration alone does not prove depth is active.
- SceneView's pinned reference documents **SurfaceMirrorer**, a GPU copy of the fully rendered camera+virtual scene into encoder surfaces. This is different from ARCore dataset recording (raw camera/sensor replay without the virtual content). Recording/streaming must validate actual composed frames, and microphone permission remains separate.
- [SceneView license](https://raw.githubusercontent.com/sceneview/sceneview/v4.62.0/LICENSE) is Apache-2.0. Android SDK/ARCore/Filament and transitive dependencies retain their own notices/terms. KayKit GLBs retain their CC0 provenance.
- [Microsoft OpenJDK official downloads](https://learn.microsoft.com/en-us/java/openjdk/download) provide JDK 21.0.13.0.2 Windows x64 with release SHA256 files. Existing system Java is only a Java 8 runtime. `scripts/setup-android.ps1` downloads verified project-local JDK/Gradle and Google command-line SDK tools; it does not change system PATH or install a global Java runtime. SDK archives are checked against Google's repository metadata and a local SHA256 provenance record is written.

Important limitation found in research: SceneView's `SceneUnderstanding.physics` property is explicitly **reserved**, not an implemented physical-room collision solver. Do not claim that setting `SceneUnderstanding.Full` supplies desk/floor physics. Native contact/navigation and recognition-to-depth alignment need their own implementation and tests. The browser Rapier work is not automatically native physics.

Follow-up source inspection found the separate implemented `rememberDepthCollider()`/`DepthCollider.floorYAt` API. The native client explicitly combines that recent world-space depth geometry with tracked horizontal plane polygons and a tested bounded gravity/contact motor. Unknown support freezes movement; no arbitrary infinite fallback floor is invented. This is floor support, not full wall/mesh physics. SDK snapshot timestamps are wall-clock milliseconds (verified in pinned `DepthMeshNode.kt`), so freshness compares the matching clock. Kotlin tests cover desk-to-lower-floor falling, missing geometry and step rejection.

Implementation will pair to the existing scoped native-world endpoint, consume actual authoritative snapshots, render independent named actors, expose camera/depth/tracking capability truthfully, and compose only after explicit camera consent. Native camera data stays local unless the user explicitly starts output. Debug signing/building is local; no public upload, paid inference, service activation or release signing is authorized by this decision. Physical ARCore hardware validation remains required even after compilation or emulated rendering succeeds.
