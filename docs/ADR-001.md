# ADR 001: executable modular deployment

Accepted 2026-10-27. Preserve the original brief and prototype as reference. Implement shared schemas, SQL migrations, durable server simulation, integrations, browser renderer and native capture in separate modules. A single long-running Fastify host initially co-locates HTTP, ingestion, worker scheduling and WebSocket rooms. This avoids distributed locking errors before a room-shard router exists. Never deploy multiple world owners for a channel. Redis fanout and independent service scaling remain a release gate.

Use PostgreSQL SQL in both environments: embedded PGlite for zero-install local execution and pg for an external PostgreSQL deployment. Local storage is durable on disk; tests use isolated in-memory databases. Atomic ledger transactions and unique logical award keys are identical across modes. External Postgres is required for production. No Docker runtime is installed on the current workstation.

Use Vite, TypeScript, semantic DOM and Three.js for the website and transparent overlay, sharing a renderer. Public pages are client rendered initially; SSR and social preview rendering remain acceptance gaps. Procedural geometry/audio avoids third-party game IP. This is an intentional implementation deviation from suggested Next.js, not a declaration of full production readiness.

## Dependency order
1. Typed contracts, SQL persistence, deterministic world and transactional economy.
2. Twitch OAuth, encrypted token lifecycle, signed durable EventSub inbox, room read tokens.
3. Public website, controller, creator settings, original portal and avatars, actual browser tests.
4. Constrained choreography, vision capture/tracking/calibration, temporal quest validation.
5. Mobile native AR project, capability gates and composed output integration.
6. Community systems, operations, security, load/restart/retention tests and release scorecard.

Live credentials, permissioned video footage, native SDK/device availability and account-owned publishing are independent validation gates. Never substitute simulator output for these tests.

## Follow-up, 2026-10-28

Public rankings, profiles and discovery now have server-rendered HTML from actual database state. Owner-consented signed SVG profile cards also render without JavaScript; their links expire and can be revoked. Streamer-detail and faction screens currently rely on the client application. The stack decision remains unchanged.
